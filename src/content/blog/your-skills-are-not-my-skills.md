title: Your Skills Are Not My Skills

If the power goes out, I want an electrician who knows what to do. If I'm about to talk to a friend, do I need someone else to tell me what to say? Would I copy the way someone else talks and pretend to be them?

I'd happily share a skill that teaches an agent how to use an internal service or check a PDF. That expertise is useful whoever's asking. The way I talk to my agent is more personal. I ask for something, see what it does, then work out how I could ask better next time. That's where my own workflow skills come from.

## Show Me Yours

There's a lot to learn from Garry Tan's [gstack](https://github.com/garrytan/gstack), Lauren Tan's [pstack](https://github.com/cursor/plugins/blob/main/pstack/README.md), Theo Browne's [tstack](https://github.com/t3dotgg/tstack) and [Matt Pocock's skills](https://github.com/mattpocock/skills). I'm curious what each person wanted their agent to do differently and how they asked for it.

Someone else's prompt might work differently with my agent. I can even ask the same agent the same thing twice and get two different replies. Before I borrow a prompt or workflow, I want to know what the person who wrote it was trying to change. Do I want the same thing from my agent?

## Always Be Evaluating

Vercel's [skills.sh](https://skills.sh/) is a good place to see what's out there. I can read through a skill and try it on its own with [`npx skills add`](https://www.skills.sh/docs/cli). If a skill covers something technical I need the agent to do, I'm happy to add it.

I'd take my time with skills that change how I direct the agent. Say I want better code reviews. I'd try one instruction on a change I know well. Does asking the agent what might break give me something I can act on? If it helps on the next few reviews too, I'd keep it. That's how I'd build up my own prompts and workflow skills, one small change at a time.

Talk to your agent the way you'd talk to a friend. In your own words.
